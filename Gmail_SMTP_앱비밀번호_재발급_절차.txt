 Gmail SMTP 앱 비밀번호(App Password) 재발급 절차 — 인수인계용
====================================================================
작성일 : 2026-09-03
관련 계정 : gailab.dev@gmail.com
관련 시스템 : H100 module_c (Tomcat, EmailService — 이메일 인증 발송)
관련 설정 파일 : application.properties 의 mail.password 항목

--------------------------------------------------------------------
[1] 언제 이 절차가 필요한가
--------------------------------------------------------------------
- 이메일 인증 발송 시 Tomcat 로그(catalina.out)에 아래와 같은 오류가
  찍히는 경우:

    javax.mail.AuthenticationFailedException:
    535-5.7.8 Username and Password not accepted

- 이 오류는 애플리케이션 코드 문제가 아니라, Gmail 계정 인증 정보
  (mail.password)가 무효화되었거나 잘못된 경우에 발생함.
- Google은 일반 로그인 비밀번호로는 SMTP 인증을 허용하지 않으며,
  반드시 "앱 비밀번호(App Password)"를 발급받아 사용해야 함.
- 앱 비밀번호는 Google 계정 보안 설정을 변경(2단계 인증 재설정 등)하면
  기존 값이 무효화될 수 있음 — 이 경우 재발급이 필요함.

--------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------
- gailab.dev@gmail.com 계정에 "2단계 인증(2-Step Verification)"이
  켜져 있어야 앱 비밀번호 발급 메뉴가 나타남.
- 꺼져 있다면 먼저 켤 것:
    Google 계정 → 보안(Security) → 2단계 인증 → 사용 설정

--------------------------------------------------------------------
[3] 앱 비밀번호 발급 절차
--------------------------------------------------------------------
1) gailab.dev@gmail.com 계정으로 로그인한 브라우저에서 아래 주소 접속
       https://myaccount.google.com/apppasswords

   (2단계 인증이 꺼져 있으면 이 페이지 자체가 보이지 않음 → [2] 먼저 진행)

2) 앱 이름 입력란에 식별용 이름 입력 (예: "H100 SMTP")

3) [만들기] 클릭 → 16자리 앱 비밀번호가 4자씩 띄어서 표시됨
       예: xxxx xxxx xxxx xxxx

4) 화면에 표시된 비밀번호를 복사 (이 화면을 벗어나면 다시 볼 수 없으므로
   즉시 복사할 것)

--------------------------------------------------------------------
[4] 적용 위치
--------------------------------------------------------------------
- 파일: application.properties
- 항목: mail.password

    mail.password=발급받은16자리비밀번호

  * 주의: [3]-3)에서 화면에는 공백 포함(4자씩 구분)으로 표시되지만,
    실제로 붙여넣을 때는 공백을 전부 제거한 16자리 문자열이어야 함.
  * 기존 값(예: iubkphysqwhuqeog)을 완전히 새 값으로 덮어쓸 것.

--------------------------------------------------------------------
[5] 적용 후 필수 조치
--------------------------------------------------------------------
- application.properties는 Tomcat 부팅 시점에 한 번만 읽으므로,
  파일만 수정해서는 반영되지 않음.
- 반드시 Tomcat을 재기동해야 새 비밀번호가 적용됨.
- 재기동 후 이메일 인증 발송 기능을 테스트하여 정상 발송되는지 확인.

--------------------------------------------------------------------
[6] 참고 / 향후 개선 제안
--------------------------------------------------------------------
- 같은 application.properties 안의 다른 민감정보
  (external.crypto.aes-key, external.api.weather.service-key 등)는
  이미 "코드/Git 미포함, 환경변수로만 주입" 원칙을 따르고 있음.
- mail.password는 현재 파일에 평문으로 저장되어 있어 위 항목들과
  일관성이 맞지 않음. 여유가 있을 때 아래와 같이 환경변수화하는 것을
  권장함 (필수는 아님):

    mail.password=${MAIL_PASSWORD:}
