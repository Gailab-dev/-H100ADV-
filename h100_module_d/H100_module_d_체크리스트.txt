1. SSL 키 발급 (내부 CA 서명 방식으로 변경 — 자체 서명 아님)
===================================================

[중요 — 방식 변경 안내]
기존에는 자체 서명(self-signed) 인증서를 사용했으나,
디바이스가 계속 추가되는 구조를 고려하여 내부 CA(사설 인증기관) 서명 방식으로 전환함.
CA 개인키·인증서(h100-ca.key / h100-ca.crt)는 담당자 개인 PC에서 별도 관리한다.
(관련 문서: Obsidian implementation/21-내부CA구축-디바이스인증서발급체계-작업계획서)

[Windows 로컬 발급 - PowerShell, 한 줄씩 실행]

mkdir C:\Users\<계정>\workspace\ssl-keys\module_d
cd C:\Users\<계정>\workspace\ssl-keys\module_d

# (a) 이 디바이스만의 개인키 생성
openssl genrsa -out device-<시리얼>.key 2048

# (b) 서명 요청서(CSR) 생성 — CN에 디바이스 시리얼(또는 IP) 기입
openssl req -new -key device-<시리얼>.key -subj "/CN=<시리얼>" -out device-<시리얼>.csr -addext "subjectAltName=IP:<디바이스 IP>"

# (c) 내부 CA(h100-ca.key/h100-ca.crt, 담당자 PC 별도 보관본)로 서명 → 인증서 완성
#     최초 발급 이후에는 -CAcreateserial 대신 -CAserial h100-ca.srl 사용
openssl x509 -req -in device-<시리얼>.csr -CA h100-ca.crt -CAkey h100-ca.key -CAcreateserial -out device-<시리얼>.crt -days 365 -sha256 -copy_extensions copy


[발급 확인]

openssl x509 -in device-<시리얼>.crt -noout -subject -dates -issuer
openssl x509 -in device-<시리얼>.crt -noout -ext subjectAltName

# issuer 가 "CN=H100 Internal CA" 로 나오는지 확인


[디바이스 배포]

scp C:\Users\<계정>\workspace\ssl-keys\module_d\device-<시리얼>.key C:\Users\<계정>\workspace\ssl-keys\module_d\device-<시리얼>.crt C:\Users\<계정>\workspace\ssl-keys\module_d\h100-ca.crt <계정>@<디바이스 IP>:/home/<계정>/H100/system/h100_module_d/ssl/

# 주의: 경로가 /home/<계정>/H100/system/h100_module_d/ssl/ 인지 확인 (2026-08-10 폴더명 server → system 변경 반영, 구 경로 "H100/server/..." 로 쓰지 않도록 주의)


[디바이스 권한]

chmod 600 /home/<계정>/H100/system/h100_module_d/ssl/device-<시리얼>.key
chmod 644 /home/<계정>/H100/system/h100_module_d/ssl/device-<시리얼>.crt


[파일명 참고]
module_d 는 server.key.pem·server.cert.pem 또는
device-<시리얼>.key·device-<시리얼>.crt 사용 (구현·.env 지정에 따라, TLS_CERT_FILE/TLS_KEY_FILE 값과 일치시킬 것)


[유효 기간]
1년 (365일), 매년 재발급 (재발급 시에도 자체 서명이 아니라 위 CA 서명 절차 그대로 반복)

3. HMAC 64byte 값 (module_c 와 동기화)
===================================================

[중요]
module_c 의 .env 와 반드시 동일한 값


[동기화 확인]

module_c 서버:
grep DEVICE_HMAC_KEY /home/<계정>/h100_module_c/.env

module_d 디바이스:
grep DEVICE_HMAC_KEY /home/<계정>/H100/system/h100_module_d/.env

두 결과가 반드시 일치


[불일치 시]
API 요청 모두 401 Unauthorized 실패


[재발급 절차]
1. module_c 에서 새 64byte 생성 (openssl rand -hex 32)
2. module_c/.env 반영
3. module_d/.env 에 동일한 값 반영
4. 두 서비스 재시작

5. systemctl 등록
===================================================

[서비스 파일 경로]
/etc/systemd/system/h100_module_d.service


[서비스 파일 내용]

[Unit]
Description=H100 Module D - Device Server
After=network.target
Wants=network-online.target

[Service]
Type=simple
User=<계정>
Group=<그룹>
WorkingDirectory=/home/<계정>/H100/system/h100_module_d
ExecStart=/home/<계정>/H100/system/h100_module_d/h100_module_d
Restart=on-failure
RestartSec=10
StandardOutput=append:/home/<계정>/H100/system/h100_module_d/logs/systemd.log
StandardError=append:/home/<계정>/H100/system/h100_module_d/logs/systemd_error.log
Environment="PATH=/usr/local/go/bin:/usr/bin:/bin"

[Install]
WantedBy=multi-user.target


[로그 폴더 신설]
ss
mkdir -p /home/<계정>/H100/system/h100_module_d/logs
chown <계정>:<그룹> /home/<계정>/H100/system/h100_module_d/logs


[등록·시작]

sudo systemctl daemon-reload
sudo systemctl enable h100_module_d

9. Windows CRLF 오류 해결
===================================================

[오류 메시지]
-bash: ./start.sh: /bin/bash^M: 잘못된 인터프리터


[해결]

방법 1 - dos2unix
sudo apt-get install dos2unix
dos2unix start.sh stop.sh
chmod +x start.sh stop.sh

방법 2 - sed
sed -i 's/\r$//' start.sh stop.sh
chmod +x start.sh stop.sh


[확인]

file start.sh
정상: ASCII text
비정상: ASCII text, with CRLF line terminators
