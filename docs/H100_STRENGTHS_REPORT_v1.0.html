H100 장점 보고서

실제 실행 및 파일·DB 저장 시험으로 확인한 장점과 이번 보완 사항

검증일 2026년 10월 14일 · 관제 PC: Windows / Docker Desktop · 엣지: Jetson용 ARM64 구성

검증 범위

별도 로컬 검증 DB와 합성 RTSP 시험 영상을 사용하였다. 기존 운영 DB 및 현장 장비에는 접속하지 않았다. 수동 캡처 저장과 실제 AI 이상탐지의 의미를 구분한다.

01

검증된 실행 구성

PC / 엣지 분리관제는 웹·DB·C, Jetson은 D
개별 이미지웹·C·D별 Dockerfile
데이터 보존DB와 수신 파일의 영속 볼륨

실행 책임과 배포 대상을 분리하였다. D만 사용하는 실제 엣지 구성에는 MariaDB와 관제 웹이 포함되지 않는다. PC 시험용 D와 RTSP 영상원은 별도 추가 구성으로 관리한다.

로컬 계정 admin / 1234를 최초 실행 시 준비하고, 암호화 키·장비 키는 임의 생성한다. 카카오 키는 제공받은 파일에서 읽어 로컬 환경 파일에 저장하며, 비밀 파일은 Docker 빌드 컨텍스트 및 Git 커밋에서 제외한다.

근거: ops/compose.yml, compose.edge.yml, compose.test-d.yml, start.ps1, .dockerignore.

02

수동 캡처 저장의 완결성

버튼 요청이 실제 파일과 업무 데이터로 이어지는 경로를 확인하였다. 응답만 모사하지 않고 RTSP 연결, PNG 캡처, AES 암호화, HMAC 검증, C 저장, 웹 복호화를 실행하였다.

대조 항목확인 결과
이미지합성 RTSP 영상 640 × 360 픽셀
암호문 크기46480 바이트
이벤트 ID6 · 로컬 검증 데이터
무결성저장 파일 SHA-256과 C 응답 일치
DB 상태이벤트 이미지 보유 값 1, 유형 4, 알림 1건
기존 화면 연계상세 조회 준비 성공, 실제 이미지 표시

근거: DetectionController.java, C·D의 detection.go, capture.cjs.

03

실패와 중복에 대한 방어

조건검증 결과
로그인 요청 토큰 누락403 거절
D 트리거 인증 누락401 거절
C 전송 서명 누락401 거절
동일 요청 재전송 및 동시 전송동일 이벤트 ID 반환, 요청 기록 1건 유지
알림 저장 중 DB 오류 주입실패 응답 및 트랜잭션 롤백, 이벤트·캡처 건수 불변
RTSP 영상원 중지실패 응답, 저장 이벤트 추가 없음

새 수동 캡처 경로는 기존 파일 송신 경로와 구분하여 구현하였다. 새 경로에서 확인한 인증·성공 판정 결과를 기존 모든 API의 보장으로 확대하지 않는다.

04

기존 구현의 장점

  • 파일 업로드 HMAC 검증: C가 장비 시리얼과 파일 본문을 함께 검증하는 구조를 보유하고 있다.
  • D의 C 인증서 검증: 신뢰 CA가 없으면 전송을 중단하며, 검증 생략으로 전환하지 않는다.
  • 기존 파일 우선 조회: 서버에 이미지가 있으면 장비 재접속 없이 상세 화면에서 복호화·조회할 수 있다.
  • 장비 상태의 보수적 집계: 5가지 상태와 최근 갱신 시각을 함께 고려한다.
  • 세션 없는 조회 차단: 대시보드 AJAX 조회에서 401을 확인하였다.

근거: deviceauth.go, fileSend.go, EventListServiceImpl.java, DashboardMapper.xml, LoginInterceptor.java.

05

검증 범위의 한계

장점은 확인된 코드와 로컬 실행 결과에 한정된다. 실제 AI 판정 정확도, 실장비 카메라 성능, PTZ 구동, 현장 TLS 및 네트워크, 운영 DB 정합성은 검증 완료 대상이 아니다. 구체적인 문제와 개선 순서는 문제점·개선 보고서에 정리하였다.
