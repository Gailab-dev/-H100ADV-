H100 문제점·개선 보고서

기존 코드의 위험, 실행 중 확인한 오류 및 개선 우선순위

검증일 2026년 10월 14일 · 관제 PC: Windows / Docker Desktop · 엣지: Jetson용 ARM64 구성

검증 범위

별도 로컬 검증 DB와 합성 RTSP 시험 영상을 사용하였다. 기존 운영 DB 및 현장 장비에는 접속하지 않았다. 수동 캡처 저장과 실제 AI 이상탐지의 의미를 구분한다.

01

우선순위와 판정 기준

발견 사항을 운영 전 해결, 단기 개선, 후속 검증으로 구분하였다. 실행 중 확인한 현상과 소스 검토에서 발견한 위험을 각각 표시한다.

우선순위문제근거 유형
운영 전 해결기존 제어·이벤트 API의 인증 범위 불균일소스 검토
운영 전 해결기존 D 파일 전송의 HTTP 실패 응답 처리소스 검토
운영 전 해결기존 영상 프로세스 동시 접근·종료 처리소스 검토
단기 개선카카오 도메인 거절 및 날씨 키 누락실행 확인
단기 개선시간 표시·고정 폭·페이지 제목화면·API 확인
후속 검증Jetson 실장비 부하·카메라·PTZ코드 경계 확인, 실장비 미검증
운영 준비의 남은 조건

컨테이너 기동 성공과 현장 운영 준비 완료는 동일하지 않다. 이번에 누락된 실행 구성과 수동 캡처 저장 경로를 보완하였으나, 아래의 기존 기능 위험은 별도로 남아 있다.

02

기존 C·D 통신의 문제

대상확인 내용개선 및 완료 기준
D FileSenderHTTP 요청이 성립하면 수신 응답 상태가 4xx·5xx여도 true를 반환하는 경로가 있다.2xx와 저장 확인 응답을 함께 확인하고, 실패·재시도 테스트를 추가한다. 새 수동 캡처 경로는 별도 검증한다.
C 기존 수신 API일반 파일 수신에는 HMAC이 있으나 기존 이벤트·상태·통화 트리거 경로의 인증 정책이 동일하지 않다.장비 인증·본문 서명·재전송 정책을 경로별로 통일한다.
C 파일 크기 제한ParseMultipartForm의 메모리 임계값을 전체 업로드 크기 제한처럼 주석 처리하고, 뒤에서 전체 파일을 메모리로 읽는다.전체 요청 크기를 강제 제한하고 대용량·임시파일 정리 테스트를 추가한다.
Java의 기존 D 연결기존 ApiServiceImpl은 호스트명 검증을 항상 통과시키는 임시 로직을 보유한다.실제 주소의 SAN 인증서를 배포하고 기본 호스트명 검증으로 복구한다. 새 캡처 연결은 기본 검증을 유지한다.
소스 설정기존 설정에 DB 접속값과 고정 암호화 설정이 남아 있다.운영 자격정보를 외부 설정으로 이전하고 이력 노출 여부 및 교체 필요성을 확인한다.

근거: C fileReceive.go·main.go, D fileSend.go, ApiServiceImpl.java, root-context.xml 및 기존 설정 파일. 값 원문은 보고서에서 제외하였다.

03

D 영상 처리와 장비 제어

영상 프로세스 관리

기존 CmdManager에는 잠금 없이 맵을 순회하는 코드, 프로세스 시작 이전의 종료 요청, 종료 후 항목 제거가 비활성화된 코드가 있다. 여러 요청이 동시에 발생하면 경합·잘못된 종료·항목 잔존 가능성이 있다. 단일 HLS 디렉터리를 여러 요청이 함께 정리하는 구조도 검토 대상이다.

개선 기준: 하나의 카메라당 프로세스 소유권을 명확히 하고 시작·준비·종료 상태를 구분한다. 실패한 시작에서 nil 프로세스를 종료하지 않도록 하며, 동시 요청을 포함한 race 검사를 수행한다.

실장비 제어 범위

tilting 핸들러의 PTZ 명령은 로그 기록까지만 구현되어 있다. 응답 성공을 실제 카메라 움직임의 증거로 사용해서는 안 된다. 현장 카메라의 제어 프로토콜과 성공 확인 방법을 연결해야 한다.

Jetson 성능 검증

기존 스트리밍은 libx264 CPU 인코딩이다. ARM64 바이너리나 이미지 빌드만으로 실장비 프레임률·발열·장시간 안정성을 보장할 수 없다. 원본 코덱·해상도·동시 관제 수를 정한 뒤 실측해야 한다.

근거: video.go, cmdManager.go, tilting.go. 이번 작업에서는 기본 Go 검사를 막던 로그 형식 오류 12건을 수정하였다.

04

외부 연동과 화면 현상

카카오 지도

실행 확인: 카카오 서버가 로컬 출처에 대해 domain mismatched 응답을 반환하였다. 제공된 키는 로컬 환경에 반영되었으나, 현재 접속 주소의 허용 도메인 등록이 필요하다. 사용자 요청에 따라 카카오 연동은 후속 작업으로 보류하였다. SDK URL은 HTTPS로 명시하였다.

필요 등록 주소: http://localhost:7810

날씨

실행 확인: 로컬 검증 환경에 기상청 인증키가 없어 날씨 요청은 502를 반환한다. 본 작업에 제공된 카카오 키만으로 날씨 API를 사용할 수 없다.

시간 표시와 화면 폭

로컬 DATETIME 조회값은 숫자 타임스탬프로 직렬화되며, 대시보드의 최근 응급 연락 시각에 원시 숫자가 표시되었다. API와 화면의 날짜 계약을 명확히 해야 한다. 운영 DB 정본이 없으므로 실제 운영 열 형식과의 대조도 필요하다.

1600px 화면에서 주차 단속 대상 목록의 가로 넘침이 측정되었다. 390px 대시보드는 문서 폭이 592px로 확장되었다. 관제 PC의 우선 지원 해상도를 정하고, 그 범위의 가로 넘침부터 개선한다.

대시보드·응급 연락망의 문서 제목이 비어 있고 통계 제목은 home이다. 작업표시줄 및 여러 탭 구분에 필요한 제목 정리가 필요하다.

05

데이터와 배포 준비

저장소에 운영 DB의 정식 초기화 SQL이 없어, Java 매퍼 및 Go 모델에서 사용하는 필드를 기준으로 로컬 검증 스키마를 작성하였다. 운영 DB와의 타입·제약·인덱스 일치 검증은 남아 있다. 초기 검증 자료는 운영 이력이나 실제 탐지 성능을 나타내지 않는다.

로컬 인증서는 시험용이다. Jetson에서 C에 접근하려면 관제 LAN 주소 바인딩, 실제 주소가 포함된 인증서, 신뢰 CA, 장비별 시리얼·HMAC 키 및 동일한 캡처 암호화 키를 준비해야 한다.

새 수동 캡처는 DB 트랜잭션과 파일 저장 결과를 확인한다. 다만 DB와 파일시스템을 하나의 물리 트랜잭션으로 묶을 수 없으므로, 전원 차단이나 커밋 결과 불명확 상황의 잔여 파일 점검·복구 절차와 백업 검증이 후속 과제이다.

06

개선 실행 순서

단계작업완료 판단
1 · 현장 접속카카오 허용 도메인, 날씨 키, PC·Jetson 주소, 실제 CA 및 장비 키 구성지도 타일 표시, 날씨 정상 응답, 양방향 TLS 접속 확인
2 · 통신 신뢰성기존 C·D 경로 인증 통일, FileSender 성공 판정 수정, 요청 크기 제한서명 오류·4xx·5xx·초과 업로드가 저장 성공으로 반환되지 않음
3 · 영상 안정성CmdManager 경합 제거, HLS 소유권 정리, PTZ 실장비 연결동시 시작·중지·카메라 단절 테스트 및 실제 동작 확인
4 · 데이터 기준운영 DB 정본 대조, 날짜 응답 형식 확정, 영속 데이터 백업·복원 시험기존 데이터 보존 및 대표 조회·상세·통계 일치
5 · 화면 품질PC 지원 해상도 확정, 목록 가로 넘침·탭 제목·시각 표시 개선대표 해상도 캡처 및 회귀 테스트 통과

사용자에게 새 보조 문구를 임의로 추가하지 않고, 실제 기능과 오류의 원인을 먼저 수정하는 순서로 진행한다.
